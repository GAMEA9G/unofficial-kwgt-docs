Komponents

A komponent is a reusable piece (a progress bar, a clock face, a button row) that you drop into widgets. It is packed like a widget but holds komponent.json instead of preset.json. Here is the unzipped Wave Progress Bar folder:

Wave_Progress_Bar/
├── komponent.json        (the layers, like preset.json)
├── komponent_thumb.jpg   (one preview image)
└── icons/
    ├── material.json
    └── material.ttf

Thumbnailsportrait + landscape jpgone komponent_thumb.jpg
Extra foldersbitmaps/, fonts/, icons/optional: icons/ (icon font, e.g. material.ttf) and/or bitmaps/ (images)
Extension.kwgt.komp (a ZIP archive, like .kwgt)
New fact. In komponent.json the root is a KomponentModule directly. Earlier docs said the root must be RootLayerModule; that holds for widget presets.

Packing a .komp

A .komp file is simply a ZIP archive holding the contents shown above, the same way a .kwgt is a ZIP holding preset.json. To make one, zip the contents of the folder (komponent.json, komponent_thumb.jpg, icons/) so komponent.json sits at the ZIP root, not inside an extra folder, then rename the file to .komp. To inspect one, rename it to .zip and unzip it.

Extra root fields

FieldMeaning
internal_titleName, e.g. "Wave Progress Bar".
internal_descriptionWhat it does.
internal_author_name / internal_author_emailAuthor credit, set on the root module.
globals_listPrivate settings (see below).
preset_info.width / heightNatural size (485 x 49). preset_info still holds version, title, description, author, email, features ("MUSIC"), release, locked, pflags.

Globals are the komponent’s settings

Globals live on the komponent root and never leak into the widget. index need not be in order (here 2, 3, 1). pbwidth uses $si(rwidth)/2.3$ with toggle 10, so the bar scales with the widget width. Its description ("Progress Bar Width") and min/max (0 to 720) describe it in the editor.

"globals_list": {
  "fg-color": { "index": 2, "type": "COLOR", "title": "fg-color", "value": "#FFFFFFFF" },
  "sc-color": { "index": 1, "type": "COLOR", "title": "sc-color", "value": "#9AFFFFFF" },
  "pbwidth":  { "index": 3, "type": "NUMBER", "title": "pbwidth", "description": "Progress Bar Width",
                "min": 0, "max": 720, "toggles": 10, "global_formula": "$si(rwidth)/2.3$" }
}

Gotcha: icon font paths

The "Previous" icon points at kfile://org.kustom.provider/widgets/Material3_Media_Player.kwgt/icons/material.ttf, a path inside the widget it was taken from, not this komponent’s own icons/material.ttf. The "Next" icon has no icon_set at all and still resolves its Material name. If icons look wrong after moving a komponent, check icon_set. I have not seen material.json; it is probably a name-to-glyph map. Paste it and I will document it.
